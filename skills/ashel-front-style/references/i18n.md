# Организация интернационализации / переводов

При изменении интерфейса учитывай все локали, использующиеся на проекте.

## Хранение и подключение переводов

1. Переводы для каждого языка необходимо хранить полностью в одном выделенном JSON-файле по шаблону /{some-folder}/locales/{locale}/translation.json
2. Используется один namespace
3. Все переводы подключаются сразу и входят в сборку приложения. Это делается для моментального переключения интерфейса с одного языка на другой. Если переводов слишком много (>100 KB) или слишком много языков, то имеет смысл подключать переводы динамически для оптимизации загрузки сайта.

## Ключи переводов

Фраза на основном языке используется как ключ в обоих словарях.

Например, если основной язык Русский, то выглядеть будет так:

// ru/translation.json

```json
{
  "Пополнить баланс": "Пополнить баланс"
}
```

// en/translation.json

```json title="en/translation.json"
{
  "Пополнить баланс": "Top up balance"
}
```

Если же основной язык английский, то выглядеть будет так:

```json
// ru/translation.json
{
  "Edit profile": "Редактировать профиль"
}
```

```json
// en/translation.json
{
  "Edit profile": "Edit profile"
}
```

Это делается для того, чтобы просматривая код любой человек мог сразу по ключу понять какой текст используется в разметке, без лишних лазаний по файлам и сопоставлений ключ-значение.

Правила работы с ключами:

- Повторно используй существующий ключ, если текст полностью совпадает и имеет одинаковый смысл во всех контекстах
- Соблюдай точное написание: регистр, знаки препинания и пробелы тоже являются частью ключа
- Добавлять новые ключи в конец файла, не переставляя существующие

## Запрет на вложенные ключи переводов

**Все ключи переводов должны находиться на верхнем уровне JSON. Вложенные объекты и группировка ключей запрещены.**

Не используй такую структуру:

```json
{
  "userProfile": {
    "joinDate": "В проекте с",
    "noDate": "Дата присоединения неизвестна"
  },
  "adminProfile": {
    "joinDate": "Админ с",
    "noDate": "Дата регистрации неизвестна"
  }
}
```

**Почему вложенные ключи — плохое решение**

Представь, что разработчик впервые открывает компонент и видит:

```html
<button>{t("userProfile.joinDate")}</button>
```

Он хочет узнать, какой именно текст отображается в интерфейсе.

Логичное действие — скопировать `userProfile.joinDate` и выполнить глобальный поиск по проекту.

Но поиск не приведёт его к переводу. В JSON нет строки `userProfile.joinDate`: `userProfile` и `joinDate` находятся на разных уровнях вложенности.

Чтобы найти значение, разработчику придётся:

1. Искать отдельно `joinDate`.
2. Получить несколько совпадений из разных групп (`userProfile`, `adminProfile` и других).
3. Проверять родительские объекты каждого совпадения.
4. Сопоставлять структуру JSON с полным ключом из компонента.

И всё это ради того, чтобы узнать, какая фраза стоит за одним вызовом `t()`.

**Вложенные ключи превращают простейшую задачу чтения кода в ручную навигацию по структуре словаря.**

При увеличении количества переводов эта проблема только усугубляется.

Используй плоскую структуру с человекочитаемыми ключами:

```json
{
  "В проекте с": "В проекте с",
  "Дата присоединения неизвестна": "Дата присоединения неизвестна",
  "Админ с": "Админ с",
  "Дата регистрации неизвестна": "Дата регистрации неизвестна"
}
```

Теперь в компоненте:

```html
<button>{t("В проекте с")}</button>
```

Разработчик сразу видит исходный текст интерфейса, даже не открывая словарь.

Если потребуется найти перевод на другой язык, достаточно скопировать фразу и выполнить глобальный поиск — ключ присутствует в JSON в точности в таком же виде.

**Главный принцип: чтение интерфейсного кода не должно требовать расшифровки искусственных идентификаторов и навигации по вложенным объектам.**

Ключ должен быть понятен сам по себе и легко находиться обычным текстовым поиском без специальных инструментов или знаний о структуре словарей.

## Использование в разметке

Пример для React:

```tsx
import { useTranslation } from "react-i18next"

const ClaimButton = () => {
  const { t } = useTranslation()

  return <button>{t("Получить")}</button>
}
```

Для React-кода используй useTranslation(), чтобы компонент подписывался на смену языка.

## Типизация

Ключи должны быть типизированы

- Выводить типы ключей из словаря основного языка
- Подключать типизацию через `CustomTypeOptions` библиотеки i18next
- Запрещать нетипизированные динамические ключи, например `t(someString)`
- Проверять ошибки TypeScript после добавления переводов

Не обходи ошибки ключей через any, @ts-ignore или широкие приведения типов

## Состояние и переключение языка

Выбранный язык обязан запоминаться клиентом в локальном хранилище: localStorage нативно, через redux-persist (если используется redux), через прочие аналогичные инструменты.

Если язык синхронизирован с backend, то дожидаемся необходимых данных от сервера, переключаем язык на актуальный и только потом рендерим интерфейс.
Если при старте приложения нет возможности узнать серверный язык пользователя, то в приоритете используем сохранённый на клиенте выбор.
Если запуск приложения производится впервые - выбирается язык по умолчанию на основе системы пользователя. Если язык системы не подходит под locales, то ставится ближайший по смыслу язык (Например, в проекте подготовлены 2 перевода: ru и en. На сайт зашёл человек из германии. "de" !== "ru" - следовательно есть смысл по умолчанию поставить "en" locale)

## Правила добавления переводов

При добавлении или изменении текста интерфейса:

1. Определи основной язык проекта и все поддерживаемые локали.
2. Проверь, существует ли подходящий ключ в словаре.
3. Если ключ отсутствует, добавь его во все локали.
4. Для обычных строк используй текст основного языка в качестве ключа.
5. Не добавляй одинаковый ключ с разными значениями в одном словаре.
6. Не изменяй существующий ключ без проверки всех мест его использования.
7. Не оставляй текст интерфейса захардкоженным в JSX.
8. Не составляй переводимые предложения конкатенацией строк.
9. Для переменных используй интерполяцию.
10. Для множественного числа используй механизм pluralization i18next.
11. Для текста со ссылками или JSX-разметкой используй Trans из react-i18next, когда это необходимо.
12. Не используй динамические ключи.
13. Не добавляй лишние переводы, неиспользуемые ключи и пустые значения.

После изменения проверь, что:

- Ключи присутствуют во всех поддерживаемых локалях.
- Плейсхолдеры интерполяции совпадают.
- Переводы соответствуют контексту.
- TypeScript не выдаёт ошибок.
